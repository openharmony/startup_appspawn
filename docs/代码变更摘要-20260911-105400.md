# 代码变更摘要 - appspawn 主进程单线程化与 reclaim 异步化

**日期**: 2026-09-11 | **分支**: `feature/single-thread-reclaim` | 供代码检视（/ohos-dev-gitcode-pr-review）使用

## 需求概述

限定 appspawn 主进程（全部孵化器）线程数为 1（fork 孵化性能动机：多线程 fork 页表拷贝放大 + 锁继承风险），同时保留预加载后 `ReclaimFileCache` 文件页缓存回收语义。原实现以 detach 的 `std::thread` 异步执行 reclaim，是主进程多线程的直接来源，且与事件循环启动后的首个 fork 构成多线程 fork 竞争窗口。

## 核心改动点

### 1. reclaim 延迟定时器化（modules/ace_adapter/ace_adapter.cpp）

**改造前**（:493-502）：
- `MODE_FOR_APP_SPAWN`：`std::thread` detach 异步 reclaim（多线程 + fork 竞争窗口）
- 其他模式：同步 reclaim（阻塞各自 preload）

**改造后**：
- 新增 `ReclaimTimerCallback`：loop 线程一次性执行 reclaim + steady_clock 耗时打点（方案 A/B 切换的实测数据来源）
- `DlopenAppSpawn` 统一走 `LE_CreateTimer` + `LE_StartTimer(delaySec*1000, once)` 延迟调度，全孵化器一致，preload 零阻塞
- 延迟参数 `persist.appspawn.reclaim.delay`（秒，默认 32，负值回退默认）
- timer 失败降级：跳过 reclaim + ERROR 日志（不回退同步，不阻塞服务就绪）

### 2. unlock mount L3 兜底串行化（modules/sandbox/normal/sandbox_unlock_mount.cpp）

`DoSharedMountForUser` 按 `IsSpawnServer(GetAppSpawnMgr())` 分流：
- **主进程**（L1/L2 均失败后的罕见兜底）：当前线程直接调用 `MountQueueWorkerThread(*ctx, 0)` 串行消费队列，**零线程创建**
- **子进程**（L1 prefork / L2 fork 正常路径）：保留原 N 路 worker 并行（性能不变）

### 3. 线程禁令规范（AGENTS.md）

Code conventions 新增 Single-thread rule：主进程禁 `pthread_create`/`std::thread`/`std::async`/FFRT 提交；替代模式 = loop timer/watcher 或 fork 一次性子进程；锚定两个参考实现。

## 检视建议关注点

1. **时序**：timer 在 preload hook 期注册（loop 已存在但未 RunLoop），`LE_StartTimer` 超时是否从 RunLoop 启动起算（预期：从 StartTimer 调用起算）——影响"延迟 32s"语义基准
2. **降级语义**：timer 失败跳过 reclaim 是否可接受（vs 立即同步执行）
3. **IsSpawnServer 判定**：`servicePid == getpid()` 在 L1 prefork 子进程 / L2 fork 子进程中的正确性（fork 后 getpid 变化，预期成立）
4. **APPSPAWN_TEST 构建**：reclaim 调用未加 `#ifndef APPSPAWN_TEST` 保护——与改造前现状一致（ace_forward_compatibility.h 本身仅在非 APPSPAWN_TEST 下 include，单测构建此文件不参与或另有 stub）
5. **`MountQueueWorkerThread(*ctx, 0)` 直接调用**：workerId=0 在串行模式下的日志辨识
