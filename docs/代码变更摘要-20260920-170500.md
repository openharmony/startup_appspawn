# 代码变更摘要 - P-C1 cgroup 门机制基座（dry-run 武装）

**日期**: 2026-09-20 | **分支**: `feature/single-thread-reclaim` | **设计**: v2.0.1 §4/§9 M8'-M11'/§12 P-C1 | 供代码检视使用

## 需求概述

按 v2.0.1 设计实施 P-C1「机制基座（dry-run 武装）」：appspawn 主进程（5 孵化器）启动尾声自迁移入 `/dev/pids/<spawner>_main` 限制组并设 `pids.max=10000`（分阶段出厂默认，实质不约束——验证目录/权限/自迁移/自检/回滚全链路）；子进程 setcon 成功点经专用 pipe 发 6 字节帧（appId 配对键），主进程常驻 watcher 排空计数（dry-run 期未命中率 ≈100% 为预期，验证帧通道全链路 + M13'⑧ 基线）。门包裹（Enter/Leave 接入 fork 点）与 `pids.max=1` 正式值属 P-C2，本 PR 未接。

## 与设计的有意偏差（P-C1 范围裁剪，均在设计 §12 授权内）

1. M10'②③④（F1-F4 fork 点包裹）与 M12'（checkpoint）未实施——设计明定 P-C2 范围
2. 卡死态「一次性自重启重评」仅置态+告警，未接 StopAppSpawn 自重启动作——dry-run 期（limit=10000）③ 写失败即回滚路径极难触达，自重启接线随 P-C2 与 SIGCHLD 联动一并实施
3. 武装点「preload 完成标记」以 `LE_GetDefaultLoop() != NULL` 旁证（AppSpawnRun 调用时点由不变式保证）；无现成全局标记可用，避免为此扩 content 结构
4. M13' HiSysEvent 周期采样未建（P3 项）；帧未命中率以 LOGI 采样输出（每 1000 未命中帧一条），满足 dry-run 验证需求
5. GATE 表容量 32 槽/残留清单 32 项（设计未定具体值；并发在飞峰值 P0 实测后可调）

## 检视建议关注点

1. `GatePipeEvent` 帧命中消费与 `SpawnGateLeave` 的消费语义一致性（共用迁移/ESRCH/残留入列/表空关窗四步）
2. `GateRetryTimerCb` 表空判据（F10-3 规格：表非空只补迁不关窗重试）
3. `GateOpenWindow` 单存活不变式（F10-1：创建前销毁旧句柄；撤销仅绑定物理关窗成功——见 `GateCloseWindow`）
4. timer 句柄红线（R8-1：所有 stop/触发路径立即置 NULL，无重入形态）
5. cfg chown 组名（nwebspawn 特例）与 gate.c GATE_SPAWN_NAME_MAP 的一致性
6. dry-run 默认 10000 的参数路径（`GATE_LIMIT_DRYRUN_DEFAULT`，P-C2 切 1 时仅改默认值+出厂参数）
